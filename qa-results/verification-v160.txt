## Reproducing development checks

    python -m pip install -r requirements-dev.txt
    python -m pytest tests independent-results retest-results -q
    npm install
    node tests/extension_checks.mjs

Set TEST_PYTHON and BROWSER_EXECUTABLE for the browser scripts, then run the nine scripts in the table sequentially, for example:

    node tests/ui_polish_browser.mjs
    node tests/guided_browser.mjs
    node tests/copilot_browser.mjs

In Windows PowerShell, use $env:TEST_PYTHON and $env:BROWSER_EXECUTABLE to set the actual paths. End users do not need Node to start the application.

## Physical-device checks not completed and limitations

First-time installation on a clean Windows machine, the native Chrome extension and the real WhatsApp DOM/source binding/draft insertion still need local integration testing. No paid model, real Meta endpoint, receipt on a real phone or public tunnel was used. Mobile tests cover only a real local gateway with synthetic providers.

Requirement parsing still uses local rules for common building-material expressions; historical suggestions use statistics and shop rules. Inventory is an Excel snapshot with no reservation or stock deduction; customer outcomes are entered manually, and approval does not mean a sale. A person sends customer replies, and the PDF is attached separately. Each computer has independent data; upgrades retain data and .venv.
