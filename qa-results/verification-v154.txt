## Reproducing development checks

    python -m pip install -r requirements-dev.txt
    python -m pytest tests independent-results retest-results -q
    npm install
    node tests/extension_checks.mjs

Set TEST_PYTHON and BROWSER_EXECUTABLE to the actual Python and Chrome executable paths, then run the scripts in the table sequentially, for example:

    node tests/copilot_browser.mjs
    node tests/ui_polish_browser.mjs

These scripts share ports 8765/8766 and must not run in parallel. End users do not need Node to start the application. In Windows PowerShell, use $env:TEST_PYTHON and $env:BROWSER_EXECUTABLE to set the paths.

## Implementation limits and physical-device checks still needed

- First-time installation on a clean Windows machine, double-clicking the BAT launcher and installing the native Chrome extension were not tested. No real WhatsApp account was signed in; the real DOM, chat binding and draft insertion still need a local trial.
- A real model, Meta permissions, receipt on a real phone and public tunnels were not integrated or tested. Notification tests use synthetic providers; the mobile gateway is real local HTTP only. External connections are disabled by default.
- Requirement parsing uses local rules for common building-material expressions; historical suggestions use statistics and shop rules. Complex or unexplained content still requires manual confirmation or rewriting onto separate lines.
- Inventory is an imported snapshot, with no reservation or stock deduction; customer outcomes are recorded manually. Replies are sent by a person, and the PDF is attached separately.
- This round adds no database tables, changes neither the v5 review format nor approved quotation snapshots. Upgrades retain data and .venv; each computer has independent data.

Historical fix and upgrade evidence remains in the version notes and qa-results; acceptance for this version is based on this file and 1.5.4_优化与验收说明.md.
