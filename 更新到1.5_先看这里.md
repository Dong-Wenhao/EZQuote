# Updating to 1.6.1

This release uses the EzQuote dark green and mint green theme, with left navigation on desktop and top navigation plus the four-step workflow on narrow screens. The home page, records, amount cards, WhatsApp entry point, and mobile approval page have been updated together. The earlier long-inquiry and test-wait fixes remain in place. Each request supports up to 40 product requirements; oversized requests are rejected as a whole with a prompt to submit them in batches, without producing a partial quotation. The no-API mode remains the default.

When upgrading from 1.5.4, this release adds no database tables and does not change the v5 review digest or approved snapshots. Existing valid reviews remain usable. Follow the prompts if the page requests another review, or if products, quantities, or delivery details have changed. Older pending quotations from earlier releases still require another review under the existing rules.

## Computers with an older version installed

1. Press Ctrl+C in the service terminal and back up the entire old project.
2. Extract the new package. Copy the files inside wa_quote_mvp into the original project and replace existing files, while keeping the original data and .venv directories. Do not overwrite the old data directory with an empty new one.
3. Run python run.py from the original directory containing run.py and keep the terminal open. Existing accounts, catalogs, business workbooks, quotations, and files remain available. If complete business data has already been imported, there is no need to import the sample again.
4. Open chrome://extensions in Chrome, reload the current project's extension, confirm version 1.6.1, and refresh WhatsApp Web and the local workspace. Update the backend and extension together.
5. If an older, unapproved business quotation requires another review, select “Review this quotation again,” check products, quantities, and delivery details, save a new revision, and submit it again. Approved amounts and historical PDFs are not rewritten.

This release introduces no new migration. Upgrades from earlier versions still add any missing review tables automatically, without deleting users, quotations, or approval snapshots. The existing .venv remains usable; development dependencies do not affect normal startup.

## New users

Extract the complete package, run python run.py from the directory containing run.py, and open http://127.0.0.1:8765/. Python 3.10+ is required; 3.12 is recommended. Set different passwords for boss and staff. Then sign in as boss, open “Settings → Business data,” check samples/business_demo.xlsx, and confirm the import.

Load the extension directory in Chrome developer mode and refresh WhatsApp Web. No API key, paid credit, or mobile tunnel is required. Keep real AI and automatic mobile notifications disabled.

## Handling the new review prompts

- Incorrect quantity or product: edit the product row first, then select “Confirm products and view quotation.” If it differs from the original inquiry, enter the reason confirmed with the customer, select “Confirm correction and review again,” and continue only after the review passes.
- Removing a product mentioned in the original inquiry: it cannot simply disappear. Explicitly confirm that the customer canceled the item and enter a reason; otherwise restore the product row.
- Changing pickup or delivery area: confirm the fulfillment method and area, enter a reason, and review again. An inquiry that rejects pickup continues to use delivery by default.
- Double negatives or conflicting conditions: choose an explicit condition as prompted, or return to the requirements page, edit the original inquiry, and parse it again.
- Insufficient stock: update actual inventory and import it again, or confirm the quantity and alternatives. A written reason cannot bypass stock rules.
- Unclear conditions across multiple products: put each product and its intended use and preferences on its own line, then parse again.
- Ranges such as `20／30`: ask the customer for the final quantity, return to the first step, edit the original inquiry, and parse again. For unusual formats such as `1_020`, confirm the complete number before correcting it as prompted or editing the original inquiry.
- Unknown products are also listed: supply the product and quantity unless the customer has canceled them. If canceled, remove the row, explicitly select “The customer canceled this product,” and enter a reason.

Changing a relevant value invalidates the previous review and requires confirmation again. Drafts can retain reasons and the current step, but trusted review records are fetched from the server again. Expand the manual-change history on a saved quotation to view the reasons.

## Development reproduction

After installing requirements-dev.txt, run python -m pytest tests independent-results retest-results -q. The development dependencies include PyMuPDF. The mobile browser check waits for the import to complete before navigating. Run browser scripts sequentially; commands and executed results are recorded in VERIFICATION.md.

The short operating guide is 队友使用指南_1.6.docx.

## Page prompts

Wait for the backend while “Reviewing” is displayed. After the green success message appears, you can view the quotation. Expand the product card to see the original inquiry and evidence for ordinary quantities; unresolved issues remain visible on the page. Submit oversized inquiries in batches, retaining each product's specification, quantity, and delivery details. The full changes and test records are in 1.5.4_优化与验收说明.md.

At a viewport width of 900px, the interface uses left navigation; narrower screens switch automatically to top navigation. At widths of 1100px and above, the home page shows recent quotations and workflow guidance side by side. Update the frontend and backend together to version 1.6.1.
