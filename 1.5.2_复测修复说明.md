# 1.5.2 Retest Fix Notes

This document preserves the historical record of the 1.5.2 fixes. New findings and results for the then-current 1.5.3 release are in “1.5.3_自查与修复说明.md”; see VERIFICATION.md for the current logs. The 229 tests and 50 groups below belong to the previous round. Historical logs are saved separately as qa-results/backend-pytest-v152.txt and browser-results-v152.json.

A teammate's independent retest identified two types of omissions across three inputs. This round extracted the tests from the report attachment unchanged, reproduced quote creation, submission and owner approval in the original 1.5.1 release, and then fixed the program. The interface retained the blue-and-white step-by-step design, with no API requirement or additional runtime dependencies.

## Handling the Three Inputs

| Original inquiry | Actual error in 1.5.1 | Handling in 1.5.2 |
| --- | --- | --- |
| Need 20／30 bags cement 50kg. Deliver to Shah Alam. | Used 30 and allowed final approval at RM583.00 | Preserves the complete 20／30 expression, leaves quantity blank and flags the ambiguous range. Ask for the final quantity, edit the original text and parse it again |
| Need 1_020 bags cement 50kg. Deliver to Shah Alam. | Truncated the quantity to 20 and allowed final approval at RM398.00 | Preserves the complete 1_020 expression, flags its ambiguous format and does not prefill the numeric suffix. Verify the full number before making a specific correction or editing the original text |
| Need 20 bags cement 50kg and sand. Deliver to Shah Alam. | Dropped sand and approved only the cement at RM398.00 | Keeps the cement and unknown requirement separately. Sand lacks a product and quantity, so quoting is blocked. Complete the details, or remove the line after the customer cancels it and save the cancellation reason |

Without clarification or a manual correction, all three original inputs return NEEDS_INFO. Even a direct backend review request using the old incorrect quantities 30/20, or cement alone, cannot obtain a review_id. Bypassing review and creating a quote directly returns 409; direct pricing returns 422. No approvable quote is created.

## Fix Approach

The number scanner first reads the complete expression using the unit as an anchor, then validates it. Underscores, consecutive separators, scientific notation and the special Unicode characters covered by the tests remain in the original evidence; matching must not restart after them and accept a numeric suffix. NFKC is used only to help recognize ranges, without directly changing the quantity or the entire original text. Positions still refer to the original text. A valid 1,020 remains 1020 and is still subject to stock limits; English and Malay hyphenated quantities remain supported.

When one side of a product conjunction is recognized, the other side no longer has to belong to the existing catalog. Only text that can be clearly explained as a preference, specification, logistics detail or polite expression may be attached back to the product. Other text remains a requirement item. Unknown products joined by English and, Malay dan or Chinese 和 are retained. An unknown segment containing a preference or logistics detail is not discarded merely because it includes a modifier.

The existing backend correction contract remains in effect: removing an unknown product requires confirmation of the specific cancellation and its reason; replacing an unknown product requires separate confirmation of its SKU and quantity. Approval, PDF and Excel flows for a manual cancellation were verified. The reason is stored in the review and activity records. Stock, permissions and final amounts are still calculated and checked by the server.

## Updating and Using the Release

1. Press Ctrl+C to stop the old service, then back up the original project.
2. Replace the code with the new release while preserving the original data and .venv directories. Existing complete business data does not need to be replaced by the demo workbook.
3. Run python run.py from the directory containing the original run.py, reload the Chrome extension directory and refresh the page. The backend, extension and page footer all report 1.5.2.
4. This release uses parser rules v4. Old unapproved business quotes require another review and a saved new revision. Old browser drafts retain the original inquiry but must be parsed again. Accounts and approved snapshots/PDFs are preserved.

See “队友使用指南_1.5.docx” for interface instructions. Its filename identifies the 1.5 series; its body was updated to 1.5.2.

## Verification Scope

This round used Linux, a real local backend and mobile gateway, and Chrome Headless Shell 140. Extension APIs and the WhatsApp chat DOM were simulated. No real WhatsApp account was used, no messages were sent to real numbers, and no paid model was called. First-time Windows installation by double-clicking, the native Chrome side panel and real-account integration still need verification on a teammate's computer.

Local rules cover common building-material expressions; these results do not establish that every natural-language inquiry is free from omissions. One product per line remains the recommended input format, and staff and owners must compare the original text with the item details. Excel stock is an imported snapshot, with no automatic reservation or deduction. Customer replies and PDFs still need to be sent manually.
