# 1.5 Self-Review Revision Notes

This document preserves the historical revisions from 1.5 to 1.5.1. The version described as current in this record is 1.5.3; see “1.5.3_自查与修复说明.md” for its new fixes and VERIFICATION.md for current verification results. The 187 tests and 47 groups below belong to the previous round, with historical logs in qa-results/backend-pytest-v151.txt and browser-results-v151.json.

Rechecking the previous 1.5 release package exposed previously uncovered edge cases. The following issues were fixed in program version 1.5.1 and covered by additional independent tests. Existing tests were neither deleted nor skipped. The release continued to use no-API mode.

## Reproduced and Fixed Issues

| Issue | Original 1.5 behavior | Handling in 1.5.1 |
| --- | --- | --- |
| Range or either/or quantities | “20 or 30 bags” and “20 或 30 袋” directly used 30 and indicated that a quote could be created | Preserves the full expression and asks for the final quantity; a checkbox cannot substitute for clarification. After verification, edit the original text and parse again |
| Delivery continuation lines swallowed requirements | “10 bags sand, deliver…” was discarded as a logistics-only line; “Prefer fast setting, deliver…” lost the preference | Skips only logistics-only lines. Unknown products remain separate items requiring review; continuation lines for a single product retain preferences, brands and specifications |
| Negation scope and trailing negation | A condition after an English comma could remain negated; “速凝不要” was interpreted as requesting fast-setting products | Commas limit the local scope, and common Chinese, English and Malay trailing negation is recognized. Optional conditions such as “not required” still require clarification |
| Manually added products could not be confirmed | The backend listed additions without returning a row number, so the frontend could not obtain that line's SKU and quantity | Associates the specific added row so confirmed values and reasons can be saved. The owner can see complete products and corrections |
| Invalid quantities caused server errors | Manually requesting oops or an extreme exponent could return HTTP 500 | Validates numbers, units and ranges before any Decimal normalization, returning 422 without writing a valid quote |
| Legacy price-list mode retained the old numeric defects | Its old regex could truncate 1,020 to 20 and merge equal quantities from different positions | Shares the complete-number scanner with business mode. Invalid and range quantities are blocked, and separate mentions are not merged by value |
| Upgrade caches reused old issue IDs | The browser could restore an old review reason and continue with an expired issue ID, leaving the workflow stuck | Drafts record the parser version. An old version retains the original text and customer details but must parse again; it cannot reuse old corrections or review results |
| Mobile approval lacked correction reasons and stale-review notices | The owner could not clearly see manual-correction reasons; an invalid pending quote still showed an enabled approval button | Shows corrections and reasons in all three languages. Quotes needing another review direct the user back to the desktop, block approval and retain the return action |
| Switching quotes in the same mobile tab | A second link changed only the URL fragment while the page still showed the previous quote; old responses could also arrive late | Watches link changes, clears the previous password and state, and loads the new quote. Old requests cannot overwrite the current quote; downloads remain bound to the quote selected when requested |

Actual probes against the original and revised packages are saved in qa-results/self-review-before-after.json. Tests used only synthetic products and customers and isolated databases, with no real accounts or messages.

## Added Verification

The new backend file tests/test_self_review.py contains 34 tests. They focus on complete range expressions, retention of unknown products, preferences on continuation lines, local and trailing negation, HTTP 422 for invalid values, row numbers and auditing for added products, complete numbers in legacy price lists, and review status/approval blocking on mobile.

The new tests/self_review_browser.mjs contains 7 groups using real local services and a separate mobile gateway: blocking range quantities and editing the inquiry, explicitly cancelling an unknown product, saving a manually added product, three-language mobile correction records and actual PDFs, reparsing old caches, blocking approval after business-data changes, and isolating late responses when opening a second quote link in the same tab.

The final backend result was 187 passed; all 47 groups across 7 browser scripts and 10 extension-logic groups passed. The standard recommendation remained RM471.20 and the owner-adjusted result remained RM471.60. The added-product example contained 20 bags of fast-setting cement and 5 bags of nails, approved at RM522.00 with both products retained in the PDF. This amount comes from the sample business rules and must not be treated as a universal fixed quote.

Current logs are in qa-results/backend-pytest.txt, browser-results.json and each script's txt file. Images were used only for internal inspection and were not included in the installer. The Word guide was synchronized for 1.5.3 while retaining the filename “队友使用指南_1.5.docx”.

## Functional Boundaries That Still Need to Be Clear

1. The current version can demonstrate the complete quotation cycle, but first-time installation on the user's Windows machine, the real Chrome extension side panel and real WhatsApp account integration were not performed. These results do not establish production acceptance.
2. Requirement understanding uses local rules; pricing uses historical statistics and shop rules. A real large language model and automatic WhatsApp mobile notifications were not enabled. Simulated interfaces or a local mobile page do not establish that real mobile notifications were delivered.
3. Excel data is an imported snapshot. Stock or price-list changes require reimporting. Quote records export to a separate file and do not write back to the user's original price list in real time. Stock is neither reserved nor automatically deducted, so the application cannot establish fulfillment commitments when multiple people take orders concurrently.
4. Arbitrarily complex natural language, unconfigured products and ambiguous expressions still require human verification. Use one product per line where possible. Ask for clarification before offering a definite answer when the input is ambiguous.
5. This is a single-shop local MVP with fixed owner and staff roles. Computers do not synchronize automatically. Customer replies still require human checking and sending, and PDFs are attached separately.

## Updating

Stop the service and back up the entire data directory first. Replace the code while preserving data and .venv, then run python run.py. Reload extension in Chrome, confirm that both the program and extension report 1.5.3, and refresh the page. Existing business data does not require importing the samples again. Old pending business quotes must be reviewed again and saved as new revisions; approved snapshots and PDFs are preserved.
