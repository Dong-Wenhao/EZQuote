# EzQuote 1.6.1 Final Delivery Checks

Date: October 23, 2026. This release retains the dark-green and mint-green interface and mainly corrects startup and shutdown handling. The existing flows for three-language requirement parsing, business-workbook pricing, staff review, owner approval, PDFs, reply drafts and activity records remain in place.

## Fixes in This Round

1. **Starting a second instance could open an old page.** This was reproduced: when an old service occupied port 8765, the old launcher could open that service's page before reporting startup failure. The new launcher claims the port first and waits for its own backend to start. When the port is occupied, it asks the user to close the old service. It does not open the old page, create a mobile tunnel or automatically terminate another process.
2. **Normal shutdown displayed an exception.** Pressing Ctrl+C after starting through ordinary run.py previously showed a KeyboardInterrupt traceback. The new version waits for normal backend exit and handles the stop signal following service cleanup. Actual testing confirmed that it could start again after stopping and that saved data remained available.
3. **Windows startup error messages were inaccurate.** Previously, any startup failure prompted the user to install Python. The new launcher retains the specific error output and exit code, adds instructions for an occupied port and reminds users to preserve data and .venv.

The long-input test result file now records the current version automatically, while historical 1.5.4 verification records remain intact. This change does not alter quantity parsing or business decisions.

## Actual Preservation of Existing Data

Using synthetic data, accounts were created and the business workbook imported in 1.6.0, retaining a draft, a pending quote and an approved quote. After shutdown, the files were overwritten with 1.6.1 and launched through ordinary run.py:

- Original users, passwords, valid sessions, business data and all three quote states were preserved.
- Approval snapshots were unchanged, original PDF bytes were identical, and cell values across all Excel worksheets were identical.
- The pending quote could still be approved; the draft could be submitted and returned; the approved quote could record a sale outcome and update the ledger.
- These results remained intact after another normal stop/start cycle. The original .venv dependency marker and preserved files were unchanged.

Excel downloads regenerate the workbook, so verification compares worksheet data; internal timestamps and similar metadata can vary with generation time. See VERIFICATION.md and qa-results for detailed logs.

## Applying This Update

1. Press Ctrl+C in the old command window to stop the service, then back up the original project.
2. Copy the new files into the original project and replace existing files, preserving data and .venv. New users can simply extract the complete archive.
3. Run python run.py from the directory containing run.py and keep the window open. Reload extension in Chrome, confirm version 1.6.1, then refresh WhatsApp and the workspace.
4. Follow 队友使用指南_1.6.docx to process an actual inquiry. Check the customer, products, final amount, PDF and chat source before manually sending the reply and attaching the PDF.

If the launcher reports Port 8765 is already in use, close the old service window before starting again. Do not delete data or .venv.

## Checks Still Needed on a Local Computer

This round used Linux, Python 3.12 and Chrome Headless Shell 140, with dependencies prepared beforehand. First-time installation in a clean Windows environment, the native Chrome extension and real WhatsApp pages still require a final device check on a teammate's computer. Test accounts, chats and business data were synthetic. No paid model, real Meta API, real mobile receipt or public tunnel was used.

The current demonstration leaves real AI and automatic mobile notifications disabled. Local rules organize requirements; statistics and shop rules provide price recommendations. Stock is an imported snapshot, customer outcomes are recorded manually, replies are checked and sent by a person, and PDFs are attached separately. Owner approval and customer purchase are recorded as separate events.
